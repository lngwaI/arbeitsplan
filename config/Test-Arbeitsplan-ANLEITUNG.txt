ARBEITSPLAN - TEST IN DER FIRMA, SCHRITT FÜR SCHRITT
====================================================
Dieser Ordner wird automatisch aus dem abgenommenen Stand erzeugt (scripts\test-arbeitsplan.cmd).
Welche Version es ist, steht in VERSION.txt (Commit + Prüfsumme der exe).

INHALT
  0_ANLEITUNG.txt        diese Datei (für dich, nicht aufs Laufwerk)
  VERSION.txt            Stand und Prüfsumme (für dich und die IT)
  1_Aufs-Laufwerk\       NUR der Ordner Arbeitsplan_Test darin kommt aufs Laufwerk
  2_Fuer-die-IT\         IT-Unterlage (Freigabe, Ordnerrechte, offene Fragen), Kurzanleitung, Übersicht
  3_Zum-Ausdrucken\      Übersicht "Was liegt wo?" zum Zeigen, Unterlagen für das Gespräch (nicht aufs Laufwerk)


SCHRITT 0 - VORHER (Pflicht)
  [ ] OK vom Vorgesetzten, dass getestet werden darf.
  [ ] OK der IT: Wie kommt der Ordner in die Firma (USB? Download? die IT kopiert ihn)?
      NICHT eigenmächtig per USB-Stick oder Mail. Ohne Freigabe nichts auf Firmen-PCs starten.
  [ ] IT-Unterlage aus 2_Fuer-die-IT übergeben.


SCHRITT 1 - AUFS LAUFWERK
  Den Ordner 1_Aufs-Laufwerk\Arbeitsplan_Test so wie er ist in einen eigenen Testordner auf dem
  Laufwerk legen, NICHT zum echten (alten) Arbeitsplan, z. B.
      \\Server\Freigabe\Abteilung\Arbeitsplan_Test\
  Danach sieht es dort so aus:
      Arbeitsplan_Test\
        LIESMICH.txt           Kurzanleitung für alle
        Programm\              Arbeitsplan.exe, Arbeitsplan.ini
        daten\                 noch leer (nur Pakete\Testprodukt.apkg und sicherung\)
  Prüfen, ob beim Kopieren nichts kaputtging (Eingabeaufforderung im Ordner Programm):
      certutil -hashfile Arbeitsplan.exe SHA256       -> muss mit VERSION.txt übereinstimmen


SCHRITT 2 - EINRICHTEN (nur du, einmal)
  1. Eigenen Windows-Anmeldenamen anzeigen: Eingabeaufforderung -> whoami
     Ergebnis DOMÄNE\name -> nur "name" verwenden.
  2. Programm\Arbeitsplan.ini mit dem Editor öffnen, eintragen:  Admins=name   speichern.
  3. Programm\Arbeitsplan.exe doppelklicken.
     "Neuen Arbeitsplan einrichten?" -> Ja.  (Der Ordner daten wird danach versteckt.)
  4. "Verknüpfung auf dem Desktop anlegen?" -> Ja.
  5. Hilfe -> Info: Version, Datenordner, Nutzer, Domäne notieren (unten).
  Blockiert Windows den Start ("Richtlinie", "App Control", SmartScreen): NICHT umgehen,
  Foto/Wortlaut der Meldung notieren und an die IT geben.


SCHRITT 3 - KOLLEGEN ANLEGEN
  Einstellungen -> Nutzerverwaltung -> "+": Windows-Anmeldename, Kürzel, Rolle
  (Leser = nur ansehen, Produktion = eintragen, Admin = alles).


SCHRITT 4 - WAS DIE KOLLEGEN TUN (sonst nichts!)
  1. Auf dem Laufwerk Arbeitsplan_Test\Programm öffnen, Arbeitsplan.exe doppelklicken.
  2. "Verknüpfung auf dem Desktop anlegen?" -> Ja. Ab dann nur noch das Desktop-Symbol.
  Es wird NICHTS kopiert: kein Ordner auf C:, keine exe, keine ini, keine Daten.

  WAS LIEGT WO
    Programm und Daten        Laufwerk, Arbeitsplan_Test\        von dir, einmal
    Desktop-Verknüpfung       Desktop des Nutzers (OneDrive)     legt das Programm selbst an
    Offline-Stand (nur Lesen) %LOCALAPPDATA%\Arbeitsplan         legt das Programm selbst an
    gewählter Datenordner     %APPDATA%\Arbeitsplan\datenordner.txt  nur nach Dialog "Datenordner nicht gefunden"
    alles andere              -                                  nichts


SCHRITT 5 - TESTEN (abhaken, Auffälligkeiten notieren)
  [ ] Zweiter PC: aus dem Ordner starten, Verknüpfung anlegen, an einem dritten PC prüfen,
      ob die Verknüpfung dort auch da ist (OneDrive-Desktop). Mit vorhandener Verknüpfung
      fragt das Programm nicht mehr; Hilfe -> "Verknüpfung prüfen / anlegen" listet sie auf.
  [ ] Statusleiste unten: links Name · Rolle · Kürzel, rechts "Aktualisiert HH:MM"; ändert ein
      anderer PC etwas, steht dort kurz gelb "Daten von anderem PC übernommen". Titel nur
      "Arbeitsplan (√ online, aktuell)".
  [ ] Laufwerk getrennt (oder Datenordner in der ini falsch) -> Dialog "Datenordner nicht
      gefunden": Pfad als L:\... oder \\Server\...\daten eingeben -> startet; nächster Start
      ohne Dialog. Ordner ohne arbeitsplan.apdb wird abgelehnt.
  [ ] Zwei Kollegen gleichzeitig: verschiedene Zeilen ändern -> beide Änderungen bleiben.
  [ ] Zwei Kollegen gleichzeitig: dieselbe Zeile ändern -> Rückfrage mit beiden Fassungen.
  [ ] Nicht angelegter Kollege startet -> Meldung "Vorgesetzten/Admin fragen", Programm endet.
  [ ] Pakete -> Kampagne starten -> Testprodukt: Läufe erscheinen im Plan.
  [ ] Update: laufende Programm\Arbeitsplan.exe umbenennen (z. B. Arbeitsplan_alt.exe) und
      dieselbe exe neu hineinlegen -> offene Fenster zeigen "NEUE VERSION".
  [ ] Die exe allein nach C: kopieren und starten -> nur "OFFLINE" (ansehen) oder gar kein Start.
  [ ] Systemrechner (ERST nach Freigabe): Konto/Rechnername in Programm\Arbeitsplan.ini bei
      NurLesenFuer= eintragen -> dort nur ansehen.

KURZ ERKLÄRT (zum Mittesten)
  Prüfleiste / LKZ-Regel
    Unter dem Blockkopf stehen die Pflichtpunkte als Haken (LKZ, Tagesprobe, WFI ...).
    LKZ gilt je Kalenderwoche: Block belegt + Haken = grün, belegt ohne Haken = rot (ab heute
    rückwärts), leere Tage "nicht nötig", sobald die KW einen Haken hat; sonst "LKZ KWnn offen".
    Ist der Sonntag erreicht und die KW hat keinen Haken: Kopf rot "LKZ KWnn NICHT GEMESSEN".
    Ein Haken an irgendeinem Tag der KW (auch leer oder nachträglich) beendet die Warnung.
  Puffer
    Puffer je Tag: Knopf "+ Puffer" (Name, Typ mobil/stationär, Text); im Block steht je Puffer eine Zeile
    "Puffer 1: Name" mit dem Text darunter, der Typ nur als Seitenstrich (blau mobil, violett stationär;
    Tooltip erklärt ihn). Klick auf die Puffer-Zeile: bearbeiten, entfernen, hoch/runter; speichert sofort.
    Daneben Tagesprobe/WFI-Woche mit Zustand (auto/fehlt/entfällt).
    Tagesprobe: Mo-Fr Pflicht, mobil allein = automatisch erledigt; an Wochenende/Feiertag nur,
    wenn dort stationär hergestellt wird. Wochen-WFI entfällt in einer KW mit stationär.
    Alter Datenbestand: der Admin wird beim Start einmal gefragt "Standard-Pflichtpunkte für
    Puffer einrichten?"; später unter Einstellungen -> Pflichtpunkte & Feiertage ->
    "Standard Puffer einrichten" (vorhandene Einstellungen bleiben).
  Rundgänge
    Leiste über den Zeilen je KW (1./2. GMP, Kühlraum, EHS, WFI-Probenahme). Abhaken braucht
    das Recht "Rundgänge abhaken"; neben dem Haken stehen Tag und Kürzel. Alle erledigt = grüner
    Rahmen "5/5 erledigt", die Leiste bleibt offen. Rechtsklick zeigt den Verlauf.
  Schichtmodus
    Je Zeile F/S/N, nur F/S oder Tagesaufgabe (ein Feld "Erledigt von"); einstellbar unter
    Einstellungen -> Blockstruktur. Daten ausgeblendeter Schichten bleiben erhalten.
  Rollen
    Nutzerverwaltung: Leser, Produktion, Admin oder eigene Rolle; je Nutzer einzelne Rechte
    dazu oder weg. Rollen werden nie gelöscht, nur beendet.
  Plan-Datei
    Woche -> "Als Plan-Datei speichern" (.applan, nur ansehen, ohne Nutzer/Protokoll);
    Woche -> "Plan-Datei ansehen" öffnet sie in einem Nur-Lesen-Fenster.
  Offene Pflichten (Idee von Claude)
    Woche -> "Offene Pflichten dieser Woche": Liste offener LKZ, Tagesproben/WFI und Rundgänge
    der angezeigten KW (optional mit der nächsten); "Springe dorthin" zeigt den Block.
    Ist nichts offen, steht dort "Alles erledigt".
  Paket-Editor (Pakete -> Neu/Bearbeiten)
    Kopf: Produkt, Code, erste Laufnummer und die Laufanzahl; die Laufanzahl setzt den Hauptlauf einmal,
    Schritte mit "Wann: zu jedem Lauf" (z. B. Mischen, Backfill) folgen ihm. Die Tabelle zeigt je Schritt
    "Wann" (z. B. 2 Tage vor Lauf 1), Läufe/Termine und die Wiederholung im Klartext.
    Kennungstabelle: Kennungsstart ("PA 40010001") zählt die Endziffern je Lauf hoch; einzelne Läufe
    überschreiben oder aussetzen ("fällt aus").
    Kalender: Ziehen verschiebt ab diesem Lauf (Umschalt = nur dieser Lauf); Teiler zwischen Kalender
    und Vorschau ziehbar (Höhe wird gemerkt), Zoom, Rückgängig/Wiederholen.
    Puffer-Schritte erscheinen im Plan als Puffer-Liste ("+ Puffer" im Block).
  Notizen im Plan
    Text markieren, Rechtsklick -> als Notiz markieren: ganze Zeilen kursiv mit hellem Hintergrund. Notizen
    zählen nicht als Inhalt (Block gilt weiter als leer, keine Suche nach Laufnummern/Equipment darin).
  Bearbeitung übernehmen / Benachrichtigungen
    Ist ein Block von jemand anderem gesperrt, kann ein Nutzer mit dem Recht "Bearbeitung übernehmen" ihn
    mit Begründung übernehmen; der Verdrängte bekommt eine Nachricht (Hilfe -> Benachrichtigungen).
  Equipment-Liste exportieren (Woche)
    Tag, Woche, Zeitraum oder Kampagne (erkannt über die Laufnummern im Plan, Vorlauf/Nachlauf in Tagen
    einstellbar): nur Equipment-Nummern, jede einmal, Leerzeile dazwischen; Zwischenablage oder .txt.
  Statusdatei
    Optional liegt im Datenordner eine Datei equipstatus.csv (Aufbau: docs/Equipment-Status.md); das
    Programm liest sie nur. Fehlt sie oder ist älter als StatusdateiMaxAlter Stunden, gilt "nicht gereinigt".
  Änderungs-Hervorhebung (Idee von Claude)
    Übernimmt das Programm Änderungen eines anderen PCs, sind die geänderten Blöcke ca. 20 s
    blau umrandet (Ecke oben rechts), unten steht "Geändert: Di Suite 1 von XXXX". Eigene
    Änderungen und der gerade bearbeitete Block werden nicht markiert.
  [ ] Offene Pflichten: Liste passt zum Plan, "Springe dorthin" landet am richtigen Block.
  [ ] Paket-Editor: Laufanzahl ändern, Kalender ziehen, Kennungstabelle, Speichern und Übernehmen.
  [ ] Notiz markieren per Rechtsklick; Block mit nur Notiz zählt als leer.
  [ ] Gesperrten Block übernehmen: Verdrängter sieht Nachricht unter Hilfe -> Benachrichtigungen.
  [ ] Hervorhebung: an PC 2 etwas ändern, PC 1 zeigt Rahmen + Statuszeile, nach ca. 20 s weg.


NEUE VERSION EINSPIELEN
  Neuen Ordner Test-Arbeitsplan nehmen (VERSION.txt zeigt den Stand). Auf dem Laufwerk
  Programm\Arbeitsplan.exe umbenennen, die neue Arbeitsplan.exe hineinlegen. Die ini und den
  Ordner daten NICHT ersetzen (dort liegen die Testeingaben und der Schlüssel).


NACH DEM TEST
  Im Testordner liegen echte Eingaben: nicht nach Hause mitnehmen, nichts davon fotografieren.
  Ordner für den Pilot weiterverwenden oder von der IT löschen lassen.
