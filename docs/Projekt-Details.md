## Stack (entschieden)
- C# / WinForms, .NET Framework 4.0-API, x86, eine exe. Gebaut mit dem Windows-eigenen `csc` (kein SDK): `build.cmd` → `bin\Arbeitsplan.exe`.
- Warum: läuft ohne Installation auf Win 10/11, ab XP SP3 mit .NET 4.0. Keine NuGet-/Fremdpakete.
- Nur .NET-4.0-APIs, Systemschrift, kein `async`/`await`, kein C# > 5 (csc 4.x lehnt neuere Syntax ab).
- **Mindestsystem Windows 10** (Stand 2026-10-27; XP/Win7-Look und `--theme` entfernt). Ein Oberflächenmodell in `src/Win/Theme.cs` (heller, flacher Look: Segoe UI, Tageskopf ohne Fläche, Schicht-Seitenstreifen, eigene Checkbox, flache Buttons, Akzentstreifen oben, 2-px-Auswahlrahmen, flache Menüs). Farben, Schrift (Fallback Tahoma → Systemschrift), Abstände nur über `Theme.Current` (`DayLabel.cs` nutzt es auch); Zeichnen in `PlanView.Overlay`/`Theme.FillHead`. Rahmen 1 px, damit die Editoren passen.
- Mobile (Android/iOS): on hold. Später Server-API + Web-Client; deshalb `src/Core` ohne UI-Bezug halten.

## Entscheidungen und Annahmen (Stand 2026-10-24)
- **Daten (Pilot)**: Release nutzt `FileStore`: eine Datei `arbeitsplan.apdb` im Datenordner (ini `Datenordner=`, leer = `..\daten` neben `Programm\`, sonst `daten\` neben der exe; wird **nie** angelegt), GZip-XML + `Protected` (AES+HMAC) mit Schlüssel aus der versteckten Datei `arbeitsplan.key` im Datenordner (Erststart erzeugt sie; fehlt sie bei vorhandener apdb → OFFLINE, nie neu erzeugen). Schreiben unter Sperrdatei: neu einlesen → anwenden (Versionsprüfung) → atomar ersetzen, `.bak1..3`. Timer (`Abfrage=`) lädt Änderungen anderer PCs (nicht im Bearbeitungsmodus). Fehler/Manipulation → OFFLINE mit `%LOCALAPPDATA%\Arbeitsplan\cache.apdb` (DPAPI-Schlüssel `cache.key`, `CacheTage=`), nur Lesen. Die exe läuft lokal wegen Smart App Control nicht: Tests laufen im GitHub-Workflow (`.github/workflows/selftest.yml`). `NurLesen=1` = alle Starts dieser exe nur lesen; Systemrechner zentral per `NurLesenFuer=` (Login/Rechnername, `*`). Soft-Locks als Dateien `<Datenordner>\sperren`. Test-Build ohne `--data`: `MemoryStore`-Testdaten. Server nach IT-Klärung. Wochenstart vorläufig Montag; "Heute" springt auf den Montag, Tag-Pfeile verschieben das Fenster um 1 Tag.
- **Ansicht selbst gezeichnet** (`PlanView`): Wochenwechsel ~40 ms. Nur der aktive Block bekommt Eingabefelder (`MainForm.edContent/edPpl`), über Inhalt und Kürzel gelegt (`PositionEditors`). `MeasureText` addiert einen festen Rand, `TextBlock` rechnet ihn heraus.
- **Grundlegende Änderungen nur in den Einstellungen** (Menü Einstellungen → Blockstruktur…, `StructureForm`): Reihenfolge, Anzahl, Name, F/S/N-Bezeichnung, Mindesthöhe, "LKZ gemessen?"-Feld. Gilt für alle Tage (`RowInfo`), nicht im Tagesgeschäft änderbar. Zeilen werden nie gelöscht. Rechte: `EditNames` (Name, F/S/N, LKZ, neue Zeile), `EditHeight`, `SortRows`.
- **12 Standardzeilen**: Suite 1, Mix / Split, Suite 2, Puffer, **Lyo**, Freeze / Thaw, Versand, Einwaage, CIP / SIP, Raum CC + 2 leere. LKZ-Feld bei Suite 1, Mix / Split, Suite 2, Lyo.
- **LKZ gemessen?**: Feld zwischen Kopf und Inhalt mit Haken, bei Haken grün hinterlegt. Klick speichert sofort (ohne Bearbeitungsmodus, Konfliktabfrage wie sonst); im Bearbeitungsmodus wird der Haken mit dem Block gespeichert.
- **Zu-/Aufklappen (nur lokal, nicht gespeichert/synchronisiert)**: Zeile ohne Inhalt im angezeigten Zeitraum standardmäßig zugeklappt (nur Kopfleiste), mit Inhalt (oder LKZ-Haken) aufgeklappt. Klick auf den Zeilenkopf klappt um. Zugeklappt + Inhalt in einem Tag zeigt "● Inhalt". Beim Wochen-/Tageswechsel gelten wieder die Standardwerte (nichts bleibt versehentlich verborgen). Suchtreffer klappen die Zeile auf; Export klappt Zeilen mit Inhalt auf.
- Layout: Kopf `KWxx (TT.MM.JJJJ - TT.MM.JJJJ)`, Datum je Spalte. Je Zeile sind Inhaltsfeld und jedes Schichtfeld in allen 7 Spalten gleich hoch. **Schichtfeld fest mind. 3 Textzeilen** (3 Reihen 4-stelliger Kürzel mit ", "), wächst nur bei mehr. Schichten farbig (F gelb, S orange, N blau).
- Suche: Feld oben rechts (Strg+F), markiert Treffer gelb in Inhalt/Equipment/Kürzel (nicht Raumnamen), zählt die Woche; Enter springt zum nächsten Treffer (`IDataStore.Find`, auch andere Wochen). Eigenes Kürzel (`User.Kuerzel`, aus Nutzer-DB) grün.
- Bearbeitung: Doppelklick auf den Block = Bearbeitungsmodus (oranger Rahmen + Notizblock-Symbol). Ende: Strg+S, Esc (ohne Änderung: raus; mit Änderung: Rückfrage Speichern Ja/Nein/Abbrechen), anderer Block, Navigation, Schließen. Versionsprüfung je Block; Konflikt → `Conflict.Merge` (Basis = Stand bei Bearbeitungsbeginn; Inhalt zeilenweise diff3 samt Format, gleich viele Zeilen = Zeile für Zeile; F/S/N; LKZ) speichert still, wenn verschiedene Stellen geändert wurden; nur bei derselben Stelle `ConflictForm`: "Vorschlag übernehmen" (beide Fassungen, gespeicherte zuerst, bleibt im Editor), "Meine Fassung speichern", "Abbrechen". Navigation (Heute/Pfeile) holt Änderungen anderer PCs sofort (Abfrage im Hintergrund).
- **Textformat** (Recht `Format`): Formatleiste oben im Bearbeitungsmodus (Schriftart, Größe, Fett, Kursiv, 7 Farben, "Farbe…", "Standardformat") und Rechtsklick-Menü auf dem Text (auch Ausschneiden/Kopieren/Einfügen). Gilt für die Markierung bzw. den danach getippten Text. Gespeichert als `FormatSpan`s (nur Abweichungen vom Standard) im Inhalt. Einfügen ist immer Nur-Text (keine fremde Formatierung); Unterstrichen/Ausrichtung sind gesperrt. Im Editor sieht man nur manuelle Formate, Statusfarben erst nach dem Speichern.

Wiederherstellen nach Rückfrage, vorher automatische Sicherung; Protokoll wird zusammengeführt (nichts geht verloren). **APBAK2**: die `.apbak` ist mit dem Datenschlüssel (`arbeitsplan.key`, `Backup.KeyOf(store)`) per `Protected` verschlüsselt+signiert (Nutzlast wie APBAK1: GZip, Kopf, SHA-256, XML); APBAK1 bleibt lesbar; MemoryStore (Testdaten, keine Schlüsseldatei) schreibt weiter APBAK1.
- **Historie ohne Obergrenze**: Store und Sicherung löschen nie alte Wochen; `Get`/`Find`/`GetAudit` arbeiten über den ganzen Bestand ("ein Jahr zurück" und weiter). Ein späterer Server muss das ebenso halten (kein Aufräumen alter Tage).
- **Rechtsklick-Menü**: Schichtfelder und Suchfeld haben ein schlichtes Menü (Rückgängig, Ausschneiden, Kopieren, Einfügen, Alles markieren) statt des Windows-Standards (`Ui.SimpleMenu`); die Felder sind reiner Text (keine Formatierung). Umlaute und Sonderzeichen (ü ö ä ß ? @ % " ! / ( ) , ; - .) werden überall unterstützt (UTF-8 durchgängig); Testdaten verwenden echte Umlaute.
