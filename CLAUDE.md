# Arbeitsplan (internes Windows-Programm, Neubau)

Wochenplan-Anzeige/-Eingabe für BioPharma-Betrieb. Vollständige Anforderungen: `docs/anforderungen.md` (nur lesen, wenn nötig). Aufgaben: `tasks.md`.

## Stack (entschieden)
- C# / WinForms, .NET Framework 4.0-API, x86, eine exe. Gebaut mit dem Windows-eigenen `csc` (kein SDK): `build.cmd` → `bin\Arbeitsplan.exe`.
- Warum: läuft ohne Installation auf Win 10/11, ab XP SP3 mit .NET 4.0. Keine NuGet-/Fremdpakete.
- Nur .NET-4.0-APIs, Systemschrift, kein `async`/`await`, kein C# > 5 (csc 4.x lehnt neuere Syntax ab).
- **Mindestsystem jetzt Win 7 (evtl. Win 10)**, XP bleibt lauffähig. Drei Oberflächenmodelle in `src/Win/Theme.cs`: `--theme xp|win7|win10` (auch winXP/Win7 …; ohne Angabe passend zum OS), Modell steht im Fenstertitel. xp = Original-Look (Tahoma, Systemgrau, eckig, flach); win7 = Segoe UI, dezent bläuliche Flächen, leichter Verlauf in Kopfleisten (kein Glanz/Schatten – Nutzer mag ihn nicht); win10 = heller UI-Umbau-Look (Tageskopf ohne Fläche, Schicht-Seitenstreifen, eigene Checkbox, flache Buttons) + Akzentstreifen oben, 2-px-Auswahlrahmen, flache Menüs. Farben, Schrift (Fallback Tahoma → Systemschrift), Abstände nur über `Theme.Current` (`DayLabel.cs` nutzt es auch); modellspezifisches Zeichnen in `PlanView.Overlay`/`Theme.FillHead`. Rahmen 1 px in allen Modellen, damit die Editoren passen.
- Mobile (Android/iOS): on hold. Später Server-API + Web-Client; deshalb `src/Core` ohne UI-Bezug halten.

## Struktur
- `src/Core/` ohne `System.Windows.Forms`: `Model.cs` (`Entry` Inhalt+`FormatSpan`s+Kürzel+LKZ, `RowInfo` Id/Name/F-S-N/Mindesthöhe/LKZ-Feld, `IDataStore` inkl. `SaveStructure`/`Find`, `MemoryStore`+Testdaten), `Catalog.cs` (Equipment-Positionen, Bausteine), `Packages.cs` (Paket: Schritte mit Wiederholung/Abwechseln/Ausweich + Blöcke, XML `.apkg`, `Apply` mit Modi), `Users.cs` (`Perm`-Rechte, User, Rechtepakete, `UserDb`, `ILockService`), `Audit.cs` (Änderungsprotokoll `AuditEntry`, `Audit.Save` = Speichern+Protokoll), `Backup.cs` (`StoreData`, Sicherung `.apbak`), `Equipment.cs` (`IEquipmentStatusProvider`+Mock, `EquipmentMatcher`, `StatusColors`).
- `src/Win/`: `PlanView.cs` (selbst gezeichnete Wochenansicht: Layout, Zu-/Aufklappen, LKZ, Farben, Markierung, Maus), `TextLayout.cs` (Umbruch mehrfarbiger/mehrgroessiger Texte, `FontCache`), `MainForm.cs` (Menü, Leisten, Navigation, Suche, Bearbeitungsmodus, Format, Export), `StructureForm.cs`, `PackageForm.cs` (+`AlternativesPicker`), `CampaignForm.cs`, `CatalogForm.cs`, `Ui.cs`, `Export.cs` (PNG/PDF), `UserAdminForm.cs`, `HistoryForm.cs` (Verlauf), `BackupForm.cs` (Sicherung), `MainForm.Data.cs` (partial: Verlauf/Sicherung/Selbsttest dazu), `Program.cs`. `config/statuscolors.ini` wird von `build.cmd` nach `bin` kopiert.
- Aufruf: `bin\Arbeitsplan.exe [--user <login>] [--nosave]`. Testhilfen (GUI-exe, ~4–7 s warten): `--shot <png> [--size BxH] [--edit spalte,zeile] [--search text] [--scroll px] [--users | --form structure|package|package2|catalog|campaign]` (echter Bildschirmabzug, Bild mit Read ansehen; Alt-Tab/Fenster des Nutzers können hineinragen), `--bench <txt>`, `--selftest <txt>` (Admin: Zuklappen, Format, LKZ, Struktur, Paket-Export/Import/Anwenden).
- Testnutzer: `mmuster` Admin (Kürzel MUMA), `ebeispiel` Leser (BEER), `pwerk` Produktion (WEPA). Mock-Lock: Di, Zeile "Suite 1" "wird von Paula Werk bearbeitet" (mit `--user mmuster` testen). `--nosave` simuliert System-PC ohne Speichern.
- Typname `Right` nicht verwenden (kollidiert mit `Control.Right`) → `Perm`.

## Token-/Code-Effizienz (gilt für alle)
- Erst gezielt suchen (Grep/Glob), dann nur nötige Zeilen lesen (offset/limit). Keine ganzen Dateien/Verzeichnisse einlesen.
- Kleine, direkte Änderungen (Edit statt Neuschreiben). Kein Vorrats-Code, keine Abstraktion ohne zweiten Nutzer.
- Antworten kurz: Ergebnis + offene Punkte. Keine Wiederholung von Code oder Anforderungen im Chat.
- Rückfragen gebündelt in einer Nachricht. Nicht für Dinge fragen, die sich aus Code/Docs ergeben.
- Dateien klein halten (~300 Zeilen); große Dateien nicht erneut lesen, wenn gerade bearbeitet.

## Orchestrierung (Hauptagent)
Der Hauptagent plant, delegiert und prüft; er schreibt nur kleine Änderungen selbst. Subagenten (`.claude/agents/`) starten kalt: Brief muss Dateien, Ziel, "fertig wenn" und Einschränkungen enthalten, nicht "basierend auf den Funden".

| Agent | Modell / Effort | Einsatz |
|---|---|---|
| `sucher` | haiku / low | Suchen, Fragen zum Code, Zusammenfassen (nur lesen) |
| `bauer` | sonnet / medium | Implementieren klar umrissener Aufgaben, Build + Shot-Test |
| `architekt` | opus / high | Entwurf, Datenmodell, Server-/Sync-/Rechtekonzept, schwierige Bugs |
| `pruefer` | sonnet / low | Review des Diffs, Build, Shot-Test in 4:3 und 16:9, XP-API-Check |

- Der Hauptagent darf Modell und Effort pro Aufruf überschreiben (`model`, `effort`): einfache Mechanik → haiku/low, Entwurf/Risiko → opus/high.
- Parallel nur lesende oder dateidisjunkte Aufgaben. Zwei Schreiber nie an denselben Dateien.
- Subagenten antworten kurz: geänderte Dateien, Ergebnis, offene Punkte (keine Code-Wiederholung).

## Entscheidungen und Annahmen (Stand 2026-10-24)
- Prototyp-Daten nur im Speicher (`MemoryStore`), Server nach IT-Klärung. Wochenstart vorläufig Montag; "Heute" springt auf den Montag, Tag-Pfeile verschieben das Fenster um 1 Tag.
- **Ansicht selbst gezeichnet** (`PlanView`): Wochenwechsel ~40 ms. Nur der aktive Block bekommt Eingabefelder (`MainForm.edContent/edPpl`), über Inhalt und Kürzel gelegt (`PositionEditors`). `MeasureText` addiert einen festen Rand, `TextBlock` rechnet ihn heraus.
- **Grundlegende Änderungen nur in den Einstellungen** (Menü Einstellungen → Blockstruktur…, `StructureForm`): Reihenfolge, Anzahl, Name, F/S/N-Bezeichnung, Mindesthöhe, "LKZ gemessen?"-Feld. Gilt für alle Tage (`RowInfo`), nicht im Tagesgeschäft änderbar. Zeilen werden nie gelöscht. Rechte: `EditNames` (Name, F/S/N, LKZ, neue Zeile), `EditHeight`, `SortRows`.
- **12 Standardzeilen**: Suite 1, Mix / Split, Suite 2, Puffer, **Lyo**, Freeze / Thaw, Versand, Einwaage, CIP / SIP, Raum CC + 2 leere. LKZ-Feld bei Suite 1, Mix / Split, Suite 2, Lyo.
- **LKZ gemessen?**: Feld zwischen Kopf und Inhalt mit Haken, bei Haken grün hinterlegt. Klick speichert sofort (ohne Bearbeitungsmodus, Konfliktabfrage wie sonst); im Bearbeitungsmodus wird der Haken mit dem Block gespeichert.
- **Zu-/Aufklappen (nur lokal, nicht gespeichert/synchronisiert)**: Zeile ohne Inhalt im angezeigten Zeitraum standardmäßig zugeklappt (nur Kopfleiste), mit Inhalt (oder LKZ-Haken) aufgeklappt. Klick auf den Zeilenkopf klappt um. Zugeklappt + Inhalt in einem Tag zeigt "● Inhalt". Beim Wochen-/Tageswechsel gelten wieder die Standardwerte (nichts bleibt versehentlich verborgen). Suchtreffer klappen die Zeile auf; Export klappt Zeilen mit Inhalt auf.
- Layout: Kopf `KWxx (TT.MM.JJJJ - TT.MM.JJJJ)`, Datum je Spalte. Je Zeile sind Inhaltsfeld und jedes Schichtfeld in allen 7 Spalten gleich hoch. **Schichtfeld fest mind. 3 Textzeilen** (3 Reihen 4-stelliger Kürzel mit ", "), wächst nur bei mehr. Schichten farbig (F gelb, S orange, N blau).
- Suche: Feld oben rechts (Strg+F), markiert Treffer gelb in Inhalt/Equipment/Kürzel (nicht Raumnamen), zählt die Woche; Enter springt zum nächsten Treffer (`IDataStore.Find`, auch andere Wochen). Eigenes Kürzel (`User.Kuerzel`, aus Nutzer-DB) grün.
- Bearbeitung: Doppelklick auf den Block = Bearbeitungsmodus (oranger Rahmen + Notizblock-Symbol). Ende: Strg+S, Esc (ohne Änderung: raus; mit Änderung: Rückfrage Speichern Ja/Nein/Abbrechen), anderer Block, Navigation, Schließen. Versionsprüfung je Block; Konflikt → Ja (überschreiben) / Nein (im Editor bleiben).
- **Textformat** (Recht `Format`): Formatleiste oben im Bearbeitungsmodus (Schriftart, Größe, Fett, Kursiv, 7 Farben, "Farbe…", "Standardformat") und Rechtsklick-Menü auf dem Text (auch Ausschneiden/Kopieren/Einfügen). Gilt für die Markierung bzw. den danach getippten Text. Gespeichert als `FormatSpan`s (nur Abweichungen vom Standard) im Inhalt. Einfügen ist immer Nur-Text (keine fremde Formatierung); Unterstrichen/Ausrichtung sind gesperrt. Im Editor sieht man nur manuelle Formate, Statusfarben erst nach dem Speichern.
- **Export** (Recht `Export`, Menü Woche): ganze Woche als PNG, PDF (eine Seite, A4-quer-Breite, JPEG-Bild), Zwischenablage, oder als Paket. **Pakete** (Menü Pakete, Recht `ImportPackage` zum Übernehmen): `.apkg` (XML) mit Kampagnen-Schritten (siehe Paket-Editor v2) und/oder fertigen Blöcken (Wochen-Export, inkl. Format). Paket-Editor zum Planen; Übernehmen ab Startdatum in drei Modi (nur leere füllen / überschreiben / anhängen); Blöcke werden über den **Blocknamen** zugeordnet. Equipment aus dem Katalog plus freie Eingabe.
- Soft-Lock: nur Popup "Das Fenster <Überschrift> wird gerade von <Nutzer> bearbeitet.", danach trotzdem bearbeiten/speichern; Sperre verfällt nach 30 min. Speichern fehlgeschlagen: klare Meldung, Block bleibt im Bearbeitungsmodus, Navigation/Schließen blockiert bzw. Rückfrage → nichts geht verloren.
- Unbekannter Windows-Nutzer erhält im Prototyp Paket "Produktion" (später nach IT-Antwort: Leser/abweisen).
- Rechte: Lesen, Text ändern/löschen/hinzufügen, Format, EditNames, EditHeight, SortRows, Export, ImportPackage, Nutzer anlegen/bearbeiten/löschen. Pakete: Leser (Lesen, Export), Produktion (+ändern/löschen/hinzufügen, Format, ImportPackage), Admin (alle, inkl. PackageAdmin). Paket "ausgewählt" nur bei **exakt** gleichen Rechten. "Text löschen" noch nicht erzwungen.
- Equipment: Schema `H<1|2>-<T|F|X|P>-<4 Ziffern>` oder `…-<2 Ziffern>` (Regex in `EquipmentMatcher`) + `IEquipmentStatusProvider` (Mock). Erkannte Nummer: **nur die Nummer** in Statusfarbe (überschreibt manuelle Farbe); Status unbekannt/nicht abrufbar → schwarz. Status wird **nie als Text** angezeigt. Farben in `statuscolors.ini`. ein MES-System später als weiterer Provider.
- **Zeilenkopf**: Überschrift steht in jeder Spalte (auch zugeklappt), der Auf-/Zuklapp-Pfeil sitzt am rechten Rand (Stift im Bearbeitungsmodus links davon). Zugeklappt + Inhalt: orangefarbener Punkt vor dem Pfeil.
- **Paket-Editor v2** (`PackageForm`): links Ablauf aus **Bausteinen** (`Baustein`: Packen, Lauf, Splitten, Mischen, TFF Flush …), rechts je Schritt Titel, Block, Tag, Wiederholen (Anzahl, Abstand in Tagen, Startnummer → "Lauf 1, 2, 3") und eine Zeile je **Equipment-Position** (Prozesstank/Rez. Tank, Pumpe, TFF-Skid, Endverdünnungs-Skid, Reinigungstank, Verteilerstück, Schlauch …): Gerät aus der validierten Liste (oder frei eintippen, dann orange = nicht validiert), "abwechselnd" (Geräte reihum: Lauf 1 A, Lauf 2 B, Lauf 3 wieder A), **Ausweich-Equipment (Backup)**, Notiz/Bezeichnung. Vorschau zeigt den Plantext. Ausgabe je Equipment eine eigene Zeile: `<Kurzname>: <ID> (Ausweich: <ID>) <Notiz>`. Platzhalter (z. B. `H1-X-020X`, nur abweichende Stellen = X) ist optional in der Geräteliste wählbar, nicht Standard.
- **Paket = Produkt** (`Package.ProductCode`, 4 Ziffern XXYY): Laufnummer 8-stellig XXYYZZZZ (z. B. 13570030). Schritt-Art (`StepKind`): Schritt (wie bisher "Titel 1, 2, 3"), Hauptlauf ("Lauf 13570030", ZZZZ = Startnummer+i), Unterlauf (Splitten/Einfrieren: Nummern je Lauf Komma-getrennt, mehrere mit "/", 4 Ziffern bekommen den Produktcode; Plantext `Unterlauf <Nr> (aus <Hauptlauf>)`). XML: `produkt`, `art`, `unterlaeufe` (alte Pakete bleiben lesbar). **Kampagnenstart** (`CampaignForm`, beim "In Plan übernehmen"): Startdatum + erste Laufnummer (Vorschlag: nächste nach dem letzten Lauf des Produkts im Plan, `Package.LastRun`), Tabelle Lauf | Vorschlag | Gewünscht (eintippen oder −/+), "Folgende mitverschieben" (Standard an). `Apply(..., schedule)` nimmt die Tage je Lauf (`RunDate`); Rhythmus aus früheren Kampagnen wird nur als Hinweis gezeigt (Erweiterung).
- **Katalog** (`Catalog`/`CatalogForm`, Menü Einstellungen → Equipment & Bausteine, Recht `PackageAdmin`): Positionen mit Kurzform und validierten Geräten, Bausteine (Standard-Block, Positionen, "nur einmal je Kampagne", "in neuer Kampagne enthalten", Sonderereignis). "Packen" ist in jeder neuen Kampagne enthalten und `Unique`: Entfernen/erneut Einfügen nur mit `PackageAdmin`. "TFF Flush" ist Sonderereignis (eigenes Paket). Katalog liegt im `IDataStore` (später Server).
- **Änderungsprotokoll** (append-only): jedes Speichern über `TrySave` → `Audit.Save` schreibt Zeit, Login+Kürzel, Tag, Block, Stand vorher/nachher, Version (`IDataStore.AppendAudit/GetAudit`; Prototyp im `MemoryStore`, später Server atomar mit dem Speichern). Rechtsklick auf Block/Text → "Verlauf…" (Lesen genügt); "Diese Version wiederherstellen" (Recht `EditText`) lädt die Fassung in den Bearbeitungsmodus, Speichern wie gewohnt. Paket-Übernahme (`Package.Apply`) wird noch nicht protokolliert.
- **Datensicherung** (Einstellungen → Sicherung…, Recht `PackageAdmin`): eine Datei `.apbak` = GZip(Kopf "APBAK1" + SHA-256 + XML) mit Plänen, Struktur, Katalog, Protokoll; Hash-/GZip-Fehler → Datei wird abgelehnt. Ordner in `sicherung.ini` neben der exe (Standard `sicherung\`), die letzten 14 bleiben. Automatisch beim Beenden, wenn letzte > 24 h (nicht mit `--nosave`). Wiederherstellen nach Rückfrage, vorher automatische Sicherung; Protokoll wird zusammengeführt (nichts geht verloren). Geschützte Einstellungsdateien (`Protected`) gehören nicht in die Sicherung.
- **Historie ohne Obergrenze**: Store und Sicherung löschen nie alte Wochen; `Get`/`Find`/`GetAudit` arbeiten über den ganzen Bestand ("ein Jahr zurück" und weiter). Ein späterer Server muss das ebenso halten (kein Aufräumen alter Tage).
- **Rechtsklick-Menü**: Schichtfelder und Suchfeld haben ein schlichtes Menü (Rückgängig, Ausschneiden, Kopieren, Einfügen, Alles markieren) statt des Windows-Standards (`Ui.SimpleMenu`); die Felder sind reiner Text (keine Formatierung). Umlaute und Sonderzeichen (ü ö ä ß ? @ % " ! / ( ) , ; - .) werden überall unterstützt (UTF-8 durchgängig); Testdaten verwenden echte Umlaute.

## Account-Kennung
- Das Label (welcher Claude-Account) steht zu Sessionbeginn im Kontext. Falls nicht: `node scripts/claude-account.js` ausführen.
- Branches heißen `<slug>/<kurzbeschreibung>` (Slug per `node scripts/claude-account.js --slug`).
- Commits bekommen automatisch die Zeile `Claude-Account: <Label>` (Hook `.githooks/prepare-commit-msg`, `core.hooksPath` = `.githooks`).
- In tasks.md hat jede Aufgabe Label, Status, Zeitstempel, z. B. `- [ ] Login-Seite (GMX / Haupt-Account, in Arbeit, 2026-10-25 01:40)`.
- Jeder Eintrag in docs/HANDOFF.md beginnt mit Datum, Uhrzeit und Label, z. B. `## 2026-10-25 01:40 – GMX / Haupt-Account`.
- Vor dem Arbeiten prüfen, ob eine Aufgabe schon von einem anderen Account beansprucht ist; dann nicht parallel daran arbeiten.
- Ist das Label "Unbekannt", erst beim Nutzer nachfragen.

Splash.cs: rahmenloser Startbildschirm 'Guten Morgen/Tag/Abend <Vorname>' (Name per Thread/AccountManagement, Fallback Windows-Nutzer, kein Name -> nur Gruss; 'View-Only' wird normal angezeigt), mind. 1 s; Test --splash <png>, nicht bei --shot/--selftest/--bench.
